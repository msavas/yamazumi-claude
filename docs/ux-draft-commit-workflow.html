2. Interaction Patterns

Three ways to work with AI suggestions

✅ Bulk Verification
Use Case: AI suggestions look correct, user wants to verify all at once.
  1. Review timeline and work elements
  2. Click "Accept All AI Suggestions"
  3. All ghost segments → solid (verified)
  4. Ready to proceed
🔄 Click-to-Cycle
Use Case: AI marked segment as "Waste" but it's actually "Value".
  1. Click ghost segment (Waste)
  2. Immediately: Ghost → Solid + Cycles to NVA
  3. Click again: Cycles to Value
  4. Click again: Cycles back to Waste
Note: First click both verifies AND cycles. Optimized for correction workflow.
💡 AI Reasoning
Use Case: User wants to understand why AI made a categorization.
  1. Right-click any ghost segment
  2. Tooltip appears with AI reasoning
  3. Example: "AI Logic: Hands idle > 2s"
  4. Helps build trust and understanding

4. Confidence Indicators

Visual indicators help users prioritize which segments to review

Green indicator. AI is confident in this categorization. Usually safe to accept.
0.65 Medium Confidence
Yellow indicator. Review recommended. AI is somewhat uncertain.
0.45 Low Confidence
Red indicator + "?" badge. Review required. AI is uncertain about this categorization.
Draft & Commit Workflow Specifications

Bulk Actions:

  • "Accept All" Button: Converts all ghost state segments to solid state (verifies all AI suggestions)
  • Location: Toolbar/header above work elements
  • Keyboard shortcut: Ctrl/Cmd + A (when focus is on review area)
  • Visual feedback: Toast notification "All AI suggestions accepted"

Individual Corrections:

  • Click-to-Cycle: Click any ghost segment → Immediately verifies (ghost → solid) AND cycles category (Waste → NVA → Value → Waste)
  • Right-Click: Show AI reasoning tooltip (e.g., "AI Logic: Hands idle > 2s")
  • Confidence Indicators: Display 0.0-1.0 on each segment (high ≥0.7 green, medium 0.4-0.69 yellow, low <0.4 red + "?" badge)

Rationale: Bulk actions enable fast workflow for high-confidence AI results. Individual corrections maintain precision for edge cases. Click-to-cycle is optimized for correction (verify + change in one action), while "Accept All" handles bulk verification without changes.
